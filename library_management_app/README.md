# Library Management App

A Python library management learning project moving from a JSON CLI
to a FastAPI application with MySQL storage.

## Local environment

Run these commands from the school-projects directory:

```bash
cd library_management_app
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

PyMySQL[rsa] includes the dependency needed for MySQL 8 password authentication.

## Set up MySQL

Install and start MySQL 8.0 separately. Use an existing MySQL administrator
account allowed to create databases, create users, grant privileges,
and run schema migrations.

Run the installer as your normal Linux user:

```bash
python -m installer.setup_database --admin-user root
```

The administrator password is requested without displaying it and is never saved.

An administrator using a Unix socket can specify
`--admin-socket /path/to/mysql.sock`. Socket authentication must already
allow the current Linux user. For a different local TCP port, add `--port 3307`.

The installer:

- Creates the library database.
- Applies the existing migrations.
- Creates library_user for connections from 127.0.0.1.
- Grants SELECT, INSERT and UPDATE on library.books.
- Generates and saves the application password.

Schema changes remain an administrator task.
API startup does not run the installer.

## Application configuration

The installer writes library_management_app/.env:

```dotenv
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=library
DB_USER=library_user
DB_PASSWORD=<generated by installer>
```

Do not copy this password placeholder into a working configuration.

The installer preserves unrelated settings and can replace the known password
placeholders `your_password_here`, `oma_salasana` and `change_me`.
Other existing passwords are treated as configured credentials.

An existing database or account without a verifiable completed configuration
requires manual review. The installer does not overwrite or delete it.

Both .env and .env.setup-pending use Linux permissions 0600.
The repository .gitignore excludes them.

Repeating a completed installation verifies its schema, migration history,
application connection and privileges. Credentials and books are preserved.
Existing .env permissions must be 0600.

The connection module loads .env from the application directory regardless
of the current working directory. Existing exported DB environment variables
take precedence over .env.

Importing the repository does not open a database connection.
Missing required settings raise RuntimeError listing the missing variable names.

## Interrupted installation

MySQL database and user creation cannot be undone as one transaction.

If setup fails after it starts, the previous .env remains and generated
credentials are retained in .env.setup-pending. A subsequent attempt stops
for review.

Keep the recovery file private. Review the database, migration history
and account with administrator access.

After verifying the completed schema and exact account privileges,
use the pending configuration to recover .env while preserving any newer
local settings. Do not delete the pending file or generate another
password blindly.

## Start the API

From library_management_app with the virtual environment activated:

```bash
python -m uvicorn api.main:app --reload
```

Restart Uvicorn after changing .env. Remove stale exported DB environment
variables if they override the intended configuration.

Check the API at:

- http://127.0.0.1:8000/health
- http://127.0.0.1:8000/docs

The health endpoint only checks that the API responds.

The .env setup is for local development. Serverless deployment will provide
DB settings through the hosting environment.

## Legacy CLI

The CLI currently uses JSON storage while API development continues.

Run it from library_management_app:

```bash
python -m cli.main
```

## Tests

From library_management_app with the virtual environment activated:

```bash
python -m pip install pytest
python -m pytest tests/ -v
```

Unit tests do not require a MySQL server.

MySQL integration tests are opt-in. Use an isolated local MySQL instance
and configure:

- LIBRARY_TEST_MYSQL=1
- LIBRARY_TEST_MYSQL_HOST=127.0.0.1
- LIBRARY_TEST_MYSQL_PORT
- LIBRARY_TEST_MYSQL_USER
- LIBRARY_TEST_MYSQL_PASSWORD

The test administrator needs database and account creation/grant privileges.
Never point these tests at application data.

Without opt-in configuration, MySQL integration tests are skipped.
