# Library Management App

The project is moving from a JSON CLI to a FastAPI application with MySQL storage.

## Local environment

Run these commands from `library_management_app`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

`PyMySQL[rsa]` includes the dependency needed for MySQL 8 password authentication.

## Set up MySQL

Install and start MySQL 8.0 separately. Use an existing MySQL administrator
account allowed to create a database, create users, grant privileges, and run
the schema migrations. Run the installer as your normal Linux user:

```bash
python -m installer.setup_database --admin-user root
```

The administrator password is requested without displaying it. It is never
saved. An administrator using a Unix socket can specify
`--admin-socket /path/to/mysql.sock`; socket authentication must already allow
the current Linux user. For a different local TCP port, add `--port 3307`.

The installer creates `library`, applies the existing migrations, and creates
`library_user` for TCP connections from `127.0.0.1`. The application account
has only SELECT, INSERT and UPDATE privileges on `library.books`. Schema
changes remain an administrator task; API startup does not run the installer.

The generated application password is saved with these settings in
`library_management_app/.env`:

```dotenv
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=library
DB_USER=library_user
DB_PASSWORD=<generated by installer>
```

Do not copy this password placeholder into a working configuration.
The installer preserves unrelated `.env` settings and can replace the known
password placeholders `your_password_here`, `oma_salasana` and `change_me`.
Other existing passwords are treated as configured credentials. An existing
database or account without a verifiable completed configuration requires
manual review; the installer does not overwrite or delete it.

Both `.env` and `.env.setup-pending` use Linux permissions 0600. The existing
repository `.gitignore` excludes them. Repeating a completed installation
verifies its schema, migration history, application connection and privileges;
it preserves credentials and books. Existing `.env` permissions must be 0600.

MySQL database/user creation cannot be undone as one transaction. If setup
fails after it starts, the previous `.env` remains and generated credentials
are retained in `.env.setup-pending`. A subsequent attempt stops for review.
Keep this file private. Review the database, migration history and account
with administrator access. After a qualified administrator verifies the
completed schema and exact account privileges, the pending configuration can
be used to recover `.env`, preserving any newer local settings. Do not delete
the pending file or generate another password blindly.

## Start the API

```bash
python -m uvicorn api.main:app --reload
```

Restart Uvicorn after changing `.env`. Existing exported DB environment
variables take precedence over `.env`; remove stale overrides if necessary.
Check `/health` and the interactive documentation at
`http://127.0.0.1:8000/docs`. `/health` only checks that the API responds.

The `.env` setup is for local development. Serverless deployment will provide
the DB settings through the hosting environment instead.

## Tests

```bash
python -m pip install pytest
python -m pytest tests/ -v
```

MySQL integration tests are opt-in. Use an isolated local MySQL instance and
set `LIBRARY_TEST_MYSQL=1`, `LIBRARY_TEST_MYSQL_HOST=127.0.0.1`,
`LIBRARY_TEST_MYSQL_PORT`, `LIBRARY_TEST_MYSQL_USER`, and
`LIBRARY_TEST_MYSQL_PASSWORD`. The test administrator needs database and
account creation/grant privileges. Never point these tests at application data.
